Injection de dépendances ​

L'injection de dépendances permet de fournir à une classe ses collaborateurs à l'exécution plutôt que de les créer elle-même. C'est un cas de composition (lien A_UN) : Guerrier A_UNE Arme, pas une relation EST_UN, qui serait un cas d'héritage.

Objectifs d'apprentissage ​

Après cette section, tu seras capable de...

  • Appliquer le principe « programmer avec les interfaces, pas les implémentations »
  • Injecter une dépendance par constructeur
  • Injecter une dépendance par mutateur
  • Injecter une dépendance par paramètre de méthode
  • Distinguer les trois points d'injection selon la durée de vie de la dépendance

Programmer avec les interfaces ​

Guerrier dépend de l'interface Arme, pas d'une implémentation spécifique :

java
public interface Arme {
    int getDegats();
}

public class EpeeCourte implements Arme {
    @Override
    public int getDegats() {
        return 5;
    }
}

public class EpeeLongue implements Arme {
    @Override
    public int getDegats() {
        return 10;
    }
}

Injection par constructeur ​

L'arme est nécessaire dès la création du guerrier et pour toute sa durée de vie - elle est injectée par constructeur :

java
public class Guerrier {
    private final String nom;
    private final Arme arme;  // composition - A_UNE interface

    public Guerrier(String nom, Arme arme) {
        this.nom = nom;
        this.arme = arme;  // injection par constructeur
    }

    public int attaquer() {
        return this.arme.getDegats();
    }
}

Utilisation :

java
Guerrier alice = new Guerrier("Alice", new EpeeLongue());
Guerrier bob   = new Guerrier("Bob",   new EpeeCourte());

Injection par mutateur ​

Le guerrier peut aussi recevoir des pièces d'équipement au fil du temps, après sa création. Chaque pièce est injectée par un mutateur et s'ajoute à une liste :

java
public interface Equipement {
    int getBonusDefense();
}

public class Bouclier implements Equipement {
    @Override
    public int getBonusDefense() {
        return 3;
    }
}

public class Armure implements Equipement {
    @Override
    public int getBonusDefense() {
        return 5;
    }
}
java
public class Guerrier {
    private final String nom;
    private final Arme arme;
    private final List<Equipement> equipements = new ArrayList<>();

    public Guerrier(String nom, Arme arme) {
        this.nom = nom;
        this.arme = arme;
    }

    public int attaquer() {
        return this.arme.getDegats();
    }

    // injection par mutateur - chaque pièce s'ajoute à la liste
    public void equiper(Equipement piece) {
        this.equipements.add(piece);
    }

    public int getBonusDefenseTotal() {
        int total = 0;
        for (Equipement piece : this.equipements) {
            total += piece.getBonusDefense();
        }
        return total;
    }
}

Le nombre de pièces d'équipement n'est pas connu à l'avance et peut s'accumuler avec le temps :

java
Guerrier alice = new Guerrier("Alice", new EpeeLongue());
alice.equiper(new Bouclier());
alice.equiper(new Armure());

Injection par paramètre de méthode ​

Une cible d'attaque ne concerne qu'un seul appel : le guerrier la reçoit, lui inflige des dégâts, puis l'oublie. Elle n'est donc ni un attribut ni un paramètre du constructeur, mais un paramètre de la méthode :

java
public interface Cible {
    void subirDegats(int degats);
}
java
public class Guerrier implements Cible {
    // ...
    private int pointsDeVie = 100;

    // injection par paramètre de méthode - la cible ne sert qu'à cet appel
    public void attaquer(Cible cible) {
        cible.subirDegats(this.arme.getDegats());
    }

    @Override
    public void subirDegats(int degats) {
        this.pointsDeVie -= Math.max(0, degats - this.getBonusDefenseTotal());
    }
}

Comme le paramètre est de type Cible, le guerrier peut attaquer n'importe quel objet qui implémente l'interface, sans rien savoir de sa classe :

java
public class Mannequin implements Cible {
    @Override
    public void subirDegats(int degats) {
        // un mannequin d'entraînement encaisse sans jamais tomber
    }
}
java
alice.attaquer(bob);
alice.attaquer(new Mannequin());

Quelle forme d'injection choisir?

  • Constructeur : la dépendance est obligatoire et vaut pour toute la durée de vie de l'objet (l'arme du guerrier)
  • Mutateur : la dépendance s'ajoute ou change après la création de l'objet, potentiellement plusieurs fois (les pièces d'équipement)
  • Paramètre de méthode : la dépendance ne sert qu'à un appel et n'est pas conservée (la cible d'une attaque)

Trois points d'injection ​

FormeSignatureQuandDurée de vie de la relation
ConstructeurGuerrier(String nom, Arme arme)Dépendance obligatoire, fixe pour la durée de vieLa même que celle de l'objet qui la reçoit
Mutateurequiper(Equipement piece)Dépendance ajoutée ou remplacée à l'exécutionPeut varier pendant l'exécution
Paramètreattaquer(Cible cible)Dépendance variable à chaque appelLe temps d'un seul appel de méthode
