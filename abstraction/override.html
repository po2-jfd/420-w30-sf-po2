Redéfinition de méthodes (@Override) ​

La redéfinition (overriding) permet à une sous-classe d'adapter le comportement d'une méthode héritée de sa super-classe. C'est l'un des mécanismes fondamentaux du polymorphisme.

Objectifs d'apprentissage ​

Après cette section, tu seras capable de...

  • Redéfinir une méthode héritée avec @Override
  • Utiliser super.methode() pour augmenter le comportement
  • Appliquer les règles de redéfinition (visibilité, signature)

Syntaxe de base ​

java
// La classe Livre de la section sur l'héritage, augmentée d'un toString()
public class Livre {
    private String auteur;
    private String titre;
    private String isbn;

    public Livre(String auteur, String titre, String isbn) {
        this.auteur = auteur;
        this.titre = titre;
        this.isbn = isbn;
    }

    public String getAuteur() { return this.auteur; }
    public String getTitre()  { return this.titre; }
    public String getIsbn()   { return this.isbn; }

    @Override
    public String toString() {
        return this.titre + " - " + this.auteur;
    }
}

public class LivrePapier extends Livre {
    private int nbPages;

    public LivrePapier(String auteur, String titre, String isbn, int nbPages) {
        super(auteur, titre, isbn);
        this.nbPages = nbPages;
    }

    @Override
    public String toString() {
        // Augmente le comportement de la super-classe
        return super.toString() + " (" + this.nbPages + " pages)";
    }
}
java
Livre livre = new LivrePapier("Robert C. Martin", "Clean Code", "978-0-13-235088-4", 464);
System.out.println(livre.toString());
// Clean Code - Robert C. Martin (464 pages)

L'annotation @Override ​

@Override n'est pas obligatoire dans le langage Java, mais elle est fortement recommandée.

  • Si la signature de la méthode ne correspond à aucune méthode héritée, le compilateur génère une erreur
  • Rend l'intention explicite dans le code
java
@Override
public String toString() { ... }  // ✓ - redéfinition vérifiée

public String tostring() { ... }  // ✗ - nouvelle méthode, pas une redéfinition
//             ^^^-- s minuscule          @Override aurait détecté l'erreur de typo

Programmation objet II

@Override est obligatoire dans le cours de PO2.

Réutiliser, augmenter ou remplacer ​

Une sous-classe a trois façons de traiter une méthode héritée :

  • Réutiliser - ne rien faire. La méthode héritée s'applique telle quelle, gratuitement, sans qu'il soit nécessaire de la redéclarer.
  • Augmenter - redéfinir la méthode et appeler super.methode() pour ajouter au comportement hérité.
  • Remplacer - redéfinir la méthode sans appeler super, pour un comportement entièrement nouveau.

Augmenter avec super.methode() :

java
public class EmployeManager extends Employe {

    @Override
    public String toString() {
        return super.toString() + " [Manager]";
    }
}

Remplacer sans appel à super :

java
@Override
public double calculerPrime() {
    return this.getSalaire() * 0.20;  // comportement entièrement nouveau
}

Règles de redéfinition ​

Ces règles ne sont pas arbitraires : chacune découle directement de la substituabilité que l'héritage promet. Un client qui utilise la super-classe doit pouvoir utiliser la sous-classe à sa place, sans rien y changer.

  1. Même nom et mêmes types de paramètres que la méthode héritée - sinon ce n'est plus une redéfinition, mais une nouvelle méthode qui n'honore aucun contrat.
  2. Visibilité égale ou plus large (ne peut pas réduire la visibilité) - le client qui appelait la méthode sur la super-classe doit toujours pouvoir l'appeler sur la sous-classe.
  3. Contraintes de validité compatibles - la sous-classe ne peut pas exiger plus du client (précondition non renforcée), ni garantir moins en retour (postcondition non affaiblie), et doit préserver les invariants de la super-classe.
  4. Type de retour compatible (covariant - peut être un sous-type) - le client reçoit toujours, au minimum, ce qu'il attendait.
  5. Ne peut pas lancer plus d'exceptions que la méthode parent - le client n'a pas prévu d'en attraper davantage. La règle vaut pour toutes les exceptions : avec une exception non vérifiée, le compilateur ne dit rien, et le bris de contrat n'apparaît qu'à l'exécution, par l'utilisateur.
java
// Super-classe
public Livre creerCopie() { ... }

// Sous-classe - OK : LivrePapier est un sous-type de Livre (type covariant)
@Override
public LivrePapier creerCopie() { ... }

// Sous-classe - ERREUR : réduire la visibilité de public à protected
@Override
protected LivrePapier creerCopie() { ... }

Réutilisation et redéfinition ​

Deux mécanismes se ressemblent en surface, parce qu'ils partagent souvent le même nom de méthode - il faut les distinguer clairement.

Réutilisation
(méthode de la super-classe)		Redéfinition
(dans la sous-classe)
PortéeSous-classe (méthode héritée, pas redéclarée)Sous-classe (redéclare la méthode héritée)
SignatureIdentique - inchangéeIdentique - même nom, mêmes paramètres
Résolue àAucune résolution - une seule méthode existeExécution (type réel - dispatch dynamique)
ButProfiter du comportement hérité sans rien écrireAdapter le comportement hérité
À ne pas confondre avec la surcharge (overloading)

La surcharge n'a pas de lien avec l'héritage : une classe déclare une méthode avec le même nom, mais des paramètres différents. Contrairement à la redéfinition, elle est résolue à la compilation, selon le type déclaré des arguments - une classe peut surcharger une de ses propres méthodes sans aucune sous-classe impliquée.

java
public class LivrePapier extends Livre {
    private int nbPages;

    public LivrePapier(String auteur, String titre, String isbn, int nbPages) {
        super(auteur, titre, isbn);
        this.nbPages = nbPages;
    }

    // Redéfinition - même signature, adapte le comportement hérité
    @Override
    public String toString() {
        return super.toString() + " (" + this.nbPages + " pages)";
    }

    // Surcharge - même nom, signature différente, indépendante de l'héritage
    public String toString(String format) {
        return format.equals("court") ? this.getTitre() : this.toString();
    }
}

Exemple complet ​

java
public class Animal {
    private String nom;

    public Animal(String nom) { this.nom = nom; }
    public String getNom() { return this.nom; }

    public String faireUnSon() { return "..."; }

    @Override
    public String toString() { return "Animal(" + this.nom + ")"; }
}

public class Chien extends Animal {
    public Chien(String nom) { super(nom); }

    @Override
    public String faireUnSon() { return "Woof!"; }  // remplace

    @Override
    public String toString() {
        return "Chien(" + this.getNom() + ")";       // remplace
    }
}

public class Chat extends Animal {
    public Chat(String nom) { super(nom); }

    @Override
    public String faireUnSon() { return "Miaou!"; }
}
