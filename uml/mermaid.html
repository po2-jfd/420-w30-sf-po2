Mermaid ​

Mermaid est l'un des outils textes existants permettant de créer des diagrammes UML rapidement sans avoir à recourir à a des outils graphiques.

Ces diagrammes peuvent être intégrés directement à la documentation des classes dans le code et journalisée avec Git (ou autre outils de contrôle de source)

Objectifs d'apprentissage ​

Après cette section, tu seras capable de...

  • Écrire un diagramme Mermaid en syntaxe texte
  • Déclarer les différents types d'objets, relations et cardinalités en syntaxe Mermaid
  • Utiliser les commandes et directives disponibles pour un diagramme de classes

Rendu vs syntaxe

La section sur les diagrammes de classes explique le sens de la notation UML (ce que représente chaque symbole). Cette page-ci documente la syntaxe Mermaid permettant de produire ce rendu.

Syntaxe de base ​

Un diagramme Mermaid s'écrit dans un bloc de code identifié par le langage mermaid. La première ligne du bloc précise le type de diagramme (classDiagram, sequenceDiagram, erDiagram, etc.) — le reste du bloc décrit les objets et leurs relations selon la syntaxe propre à ce type.

```mermaid
classDiagram
    class MaClasse {
      +propriété int
      +méthode() void
    }
```

Ce cours utilise principalement le type classDiagram, présenté en détail à la section sur les diagrammes de classes.

Types d'objets ​

Classe ​

class NomClasse {
  visibilité nomPropriété type
  visibilité nomMéthode(paramètre type) typeRetour
}

Les visibilités disponibles sont + (public), - (privé), # (protégé) et ~ (package/interne).

Portées ​

Les notations static pour les attributs et les méthode s'identifient avec un $ à la fin de la ligne

text
```mermaid
classDiagram
    class MaClasse {
      +MA_CONSTANTE String$

      + compare(MaClasse, MaClasse) int$
    }
```

Classe abstraite ​

Une classe devient abstraite en lui ajoutant l'annotation <<abstract>>, sur sa propre ligne, après la déclaration de la classe.

Attributs et méthodes abstraites ​

Les notations abstract pour les méthodes s'identifient avec une * à la fin de la ligne

text
```mermaid
classDiagram
    class MaClasse {
      <<abstract>>
      + methodeAbstraite()*
      + autreMethodeAbstraite() int*
    }
```

Interface ​

Même principe, avec l'annotation <<interface>>.

Énumération ​

L'annotation <<enumeration>> s'inscrit à l'intérieur du corps de la classe, suivie de la liste des valeurs (une par ligne, sans visibilité ni type).

Relations ​

  • Héritage d'une classe : A --|> B
  • Implémentation d'une interface : A ..|> B
  • Dépendance (référence conservée) : A --> B
  • Dépendance (interaction seulement) : A ..> B
  • Composition : A *-- B
  • Agrégation : A o-- B
  • Association simple : A -- B

Un libellé peut être ajouté après : :

Connecteurs ​

```mermaid
classDiagram
    classA --|> classB : Héritable
    classC --* classD : Composition
    classE --o classF : Aggrégation
    classG --> classH : Association
    classI -- classJ : Lien (Fort)
    classK ..> classL : Dépendance
    classM ..|> classN : Implémenation
    classO .. classP : Lien (Faible)
```

Cardinalité (multiplicité) ​

La cardinalité s'inscrit entre guillemets, immédiatement avant chaque extrémité de la relation :

ClasseA "cardinalitéA" relation "cardinalitéB" ClasseB : libellé

Valeurs courantes : 1, 0..1, *, 1..*, 2..5.

Commandes et directives pour un diagramme de classes ​

En plus des objets et relations couverts à la section sur les diagrammes de classes, Mermaid offre quelques commandes utilitaires pour un classDiagram.

direction ​

Contrôle l'orientation du diagramme : TB (haut vers bas, par défaut), BT (bas vers haut), LR (gauche vers droite) ou RL (droite vers gauche).

Commentaires ​

Une ligne commençant par %% n'est pas rendue dans le diagramme. Utile pour annoter le code source du diagramme sans encombrer le rendu.

text
```mermaid
classDiagram
    %% Ceci est un commentaire, il n'apparaît pas dans le diagramme
    class Client {
      -nom String
    }
```

note ​

Ajoute une note libre sur le diagramme, indépendante ou rattachée à une classe précise.

text
```mermaid
classDiagram
    class Commande {
      -statut StatutCommande
    }

    note "Représente une commande passée par un client"
    note for Commande "Le statut détermine les actions possibles"
```

Style d'une classe ​

La directive cssClass (ou l'appel direct class NomClasse:::nomStyle) permet d'appliquer un style visuel à une ou plusieurs classes, par exemple pour mettre en évidence une classe centrale dans un diagramme complexe.

text
```mermaid
classDiagram
    class Commande
    class StatutCommande

    cssClass "Commande" central

    classDef central fill:#f9c74f,stroke:#333,stroke-width:2px
```

TIP

Ces commandes sont surtout utiles pour les diagrammes complexes. Pour l'essentiel des besoins du cours, la syntaxe de base présentée dans la section sur les diagrammes de classes suffit.

Intégration à la documentation du code ​

Un des principaux avantages de Mermaid, comparé à un outil graphique (ex. draw.io), est qu'il s'écrit en texte brut. Ce diagramme peut donc :

  • être versionné avec Git au même titre que le code
  • être inclus directement dans un commentaire de documentation (Javadoc) ou un fichier README.md
  • évoluer par une simple modification de texte, sans avoir à repositionner manuellement des formes

TIP

Garder le diagramme près du code qu'il documente (ex. dans le Javadoc de la classe principale) réduit le risque qu'il devienne obsolète.
