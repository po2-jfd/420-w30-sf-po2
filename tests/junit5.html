JUnit 5 - structure et annotations ​

JUnit 5 est le framework de tests unitaires utilisé dans ce cours. Il fournit les annotations pour marquer les méthodes de test et les assertions pour vérifier les résultats.

Objectifs d'apprentissage ​

Après cette section, tu seras capable de...

  • Écrire et exécuter un test JUnit 5
  • Utiliser les annotations principales (@Test, @BeforeEach, @AfterEach)
  • Employer les assertions essentielles
  • Organiser les classes de test selon les conventions du cours

Dépendance Maven ​

xml
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>5.10.2</version>
    <scope>test</scope>
</dependency>

L'auto-complétion d'IntelliJ propose les versions disponibles. Utilisez la version JUnit5 la plus récente

Structure d'une classe de test ​

java
package ca.csfoy.po2.employes;

import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class EmployeTest {

    private Employe employe;

    @BeforeEach
    void setUp() {
        this.employe = new Employe("Alice", 50_000.0, new AugmentationStandard());
    }

    @Test
    void etantDonneEmployeAvecSalaireLorsquOnRecupereSalaireAlorsRetourneSalaireInitial() {
        assertEquals(50_000.0, this.employe.getSalaire(), 0.001);
    }

    @Test
    void etantDonneAugmentationAppliqueeLorsquOnRecupereSalaireAlorsRetourneNouveauSalaire() {
        this.employe.appliquerAugmentation();
        assertEquals(51_500.0, this.employe.getSalaire(), 0.001);
    }
}

Annotations principales ​

AnnotationRôle
@TestMarque une méthode comme test
@BeforeEachExécuté avant chaque méthode de test - initialisation
@AfterEachExécuté après chaque méthode de test - nettoyage
@BeforeAllExécuté une fois avant tous les tests (méthode statique)
@AfterAllExécuté une fois après tous les tests (méthode statique)
@DisabledDésactive un test temporairement
@DisplayNameNom d'affichage personnalisé

Assertions essentielles ​

java
// Valeurs égales (toujours : expected, actual)
assertEquals(50_000.0, employe.getSalaire(), 0.001);
assertEquals("Alice", employe.getNom());

// Valeurs booléennes
assertTrue(compte.estActif());
assertFalse(compte.estBloque());

// Valeurs nulles
assertNull(employe.getDepartement());
assertNotNull(employe.getNom());

// Exception lancée
assertThrows(IllegalArgumentException.class, () -> {
    new Employe(null, 50_000.0, new AugmentationStandard());
});

// Collections
assertEquals(3, listeEmployes.size());
assertTrue(listeEmployes.contains(employe));

// Polymorphisme
assertInstanceOf(Employe.class, alice);

Ordre des paramètres

La convention JUnit est toujours assertEquals(expected, actual) - attendu en premier, puis obtenu. Un ordre inversé produit des messages d'erreur trompeurs.

java
// ✓ expected, actual
assertEquals(50_000.0, employe.getSalaire(), 0.001);

// ✗ actual, expected - message d'erreur confus
assertEquals(employe.getSalaire(), 50_000.0, 0.001);

Nombres à virgules

Il peut être pertinent d'ajouter un 3e paramètre pour indiquer la variance / précision visée lors de tests avec des nombres à virgule (float ou double)

java
assertEquals(attendu, resultat, delta)

ex :

java
assertEquals(10.0, 4.99 + 3.01, 0.01)
// précison au centième près, les chiffre à la position des milièmes est ignoré

Cycle de vie d'une classe de test ​

JUnit 5 crée une nouvelle instance de la classe de test pour chaque méthode @Test. Cela garantit l'isolation entre les tests.

Pour chaque @Test :
  1. new EmployeTest()       ← nouvelle instance
  2. @BeforeEach             ← initialisation
  3. méthode @Test           ← le test lui-même
  4. @AfterEach              ← nettoyage

Conventions du cours ​

  • Une classe de test par classe de production : Employe.java → EmployeTest.java
  • Les classes de test dans le même package que la classe testée, sous src/test/java/
  • Pas de classe de test pour les mocks (les mocks ne sont jamais testés directement)
  • Toutes les méthodes de test suivent la nomenclature étantDonné/lorsque/alors

Dépendances des tests

si les tests partage un état qui n'est pas réinitialisé entre les exécutions, il est possible que les tests fonctionnent lorsqu'ils sont exécutés individuellement, mais échouent lorsqu'il sont tous exécutés.

Exemple complet - CompteBancaireTest
java
package ca.csfoy.po2.banque;

import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

class CompteBancaireTest {

    private CompteBancaire compte;

    @BeforeEach
    void initialiser() {
        this.compte = new CompteBancaire("Alice", 500.0);
    }

    @Test
    void etantDonneCompteAvecSoldeLorsquOnRecupereLeSoldeAlorsRetourneSoldeInitial() {
        assertEquals(500.0, this.compte.getSolde(), 0.001);
    }

    @Test
    void etantDonneMontantValideLorsquOnDeposeAlorsLeSoldeAugmente() {
        this.compte.deposer(200.0);
        assertEquals(700.0, this.compte.getSolde(), 0.001);
    }

    @Test
    void etantDonneSoldeInsuffisantLorsquOnRetireAlorsRetraitImpossible() {
      assertThrows(IllegalStateException.class, () -> {
            this.compte.retirer(1000.0);
        });
    }

    @Test
    void etantDonneMontantNegatifLorsquOnDeposeAlorsDepotImpossible() {
        assertThrows(IllegalArgumentException.class, () -> {
            this.compte.deposer(-100.0);
        });
    }
}
