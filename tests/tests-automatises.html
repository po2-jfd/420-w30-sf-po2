Test automatisés ​

Nomenclature et structure à utiliser pour l'écriture des tests dans le cours de PO2

Objectifs d'apprentissage ​

Après cette section, tu seras capable de...

  • Nommer correctement une méthode de test selon la convention Étant donné / Lorsque / Alors
  • Structurer un test selon le patron Arrange / Act / Assert
  • Identifier la valeur d'un test
  • Reconnaître un bon test d'un mauvais test

La convention de nommage ​

étantDonné[ÉtatInitial]Lorsque[Déclencheur]Alors[RésultatAttendu]

Les trois parties décrivent :

PartieQuestionExemple
étantDonné...Dans quel état se trouve le système?etantDonneUnArticleDePanier
lorsque...Quelle action est déclenchée?lorsquOnCalculeLePrix
alors...Quel est le résultat attendu?alorsRetourneLePrixTotal

Exemples de noms valides ​

java
void etantDonneUnArticleDePanierLorsquOnCalculeLePrixAlorsRetourneLePrixTotal()
void etantDonneEmployeAvecSalaireLorsquAugmentationAppliqueeAlorsNouveauSalaireCorrecte()
void etantDonneNomVideLorsquOnCreeLEmployeAlorsEstInvalide()
void etantDonnePanierVideLorsqueCompterContenuAlorsRetourneZero()

Règle - pas de « et » dans le nom

Un test ne doit vérifier qu'un seul comportement à la fois. Si le nom du test contient « et », il teste probablement trop de choses.

java
// ✗ Trop de choses vérifiées
void etantDonneEmployeLorsquAugmentationAppliqueeAlorsSalaireInitialInchangeEtNouveauSalaireAnnuelValide()

// ✓ Deux tests séparés
void etantDonneEmployeLorsquAugmentationAppliqueeAlorsNouveauSalaireAnnuelValide()
void etantDonneEmployeLorsquAugmentationAppliqueeAlorsSalaireInitialInchange()

Trucs de nomenclature ​

Langage ​

Toujours utiliser le langage fourni par le domaine du problème. Si le domaine parle de Produit, on ne doit pas utiliser Item ou Article pour nommer le test.

Description des contraintes ​

On évite d’utiliser le détail des contraintes dans le nom des tests. Si on doit inclure une contrainte dans le nom d’un test, on doit décrire la contrainte.

✅ Faire

public void etantDonneeDeLEauLorsquElleAtteintLePointDeCongelationAlorsLEauGele() {...}

❌ Éviter

public void etantDonneeDeLEauLorsquElleAtteintZeroAlorsLEauGele() {...}

Dans l’exemple ci-dessus, le point de congélation peut être présumé à 0°C (ou 32°F). Il n’est pas nécessaire de savoir comment est représentée la température dans le programme pour déterminer de l’exactitude de ce qui est testé.

Détails d'implémentation ​

On évite de décrire comment le code résout le problème mentionné par le test. Si on fait la validation de données par exemple, on ne parle pas d’exception dans le nom du test, on indique la validité du résultat.

✅ Faire

java
public void etantDonneeUnProduitLorsqueCreeAvecUnNomEtUnPrixAlorsEstValide () {...}
public void etantDonneeUnProduitLorsqueCreeSansNomAlorsEstInvalide () {...}

❌ Éviter

java
public void etantDonneeUnProduitLorsqueCreeAvecUnNomEtUnPrixAlorsNeLancePasDException () {...}
public void etantDonneeUnProduitLorsqueCreeSansNomAlorsLanceUneException() {...}

Le patron AAA - Arrange-Act-Assert ​

La structure interne d'un test suit toujours trois phases clairement séparées :

Séparations explicites (avec commentaires) ​

java
@Test
void etantDonneUnArticleDePanierLorsquOnCalculeLePrixAlorsRetourneLePrixTotal() {
    // ARRANGE - état initial
    Produit produit = new Produit("Clavier", 49.99)
    PanierArticle article = new PanierArticle(produit, 3);

    // ACT - action testée
    double prixTotal = article.calculerPrix();

    // ASSERT - vérification
    assertEquals(149.97, prixTotal, 0.001);
}

Séparations implicites (par lignes vides) ​

Dans les tests simples, les commentaires peuvent être remplacés par des lignes vides :

java
@Test
void etantDonneUnArticleDePanierLorsquOnCalculeLePrixAlorsRetourneLePrixTotal() {
    Produit produit = new Produit("Clavier", 49.99)
    PanierArticle article = new PanierArticle(produit, 3);

    double prixTotal = article.calculerPrix();

    assertEquals(149.97, prixTotal, 0.001);
}

Correspondance ELA et AAA ​

Nomenclature ELAPatron AAAQuestion
Étant donné...ArrangeQuel est l'état initial?
Lorsque...ActQuelle action déclenche le comportement?
Alors...AssertQuel résultat est attendu?

Caractéristiques d'un bon test ​

Un bon test :

  • Est bien nommé (Étant donné / Lorsque / Alors)
  • Est bien structuré (Arrange / Act / Assert)
  • Comporte au moins une assertion
  • Ne contient pas de « et » ni de « ou » dans son nom (à l’exception des propriétés fournies à un constructeur)
  • Est déterministe - produit toujours le même résultat
  • Est indépendant - ne dépend pas de l'ordre d'exécution des autres tests
java
// ✗ Test qui ne teste rien
@Test
void etantDonneEmployeLorsquOnLeCreerAlorsOK() {
    Employe employe = new Employe("Alice", 50_000.0, new AugmentationStandard());
    // Pas d'assertion!
}

// ✓ Test avec assertion
@Test
void etantDonneNomValideLorsquOnCreerEmployeAlorsNomConserve() {
    Employe employe = new Employe("Alice", 50_000.0, new AugmentationStandard());

    assertEquals("Alice", employe.getNom());
}
